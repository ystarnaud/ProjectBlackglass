# Phase 12 manual test plan: inventory, equipment and loot

Play `ProceduralMission` (Blind preset). The scene now **opens on the loadout panel** and generates nothing until you press `Deploy (new seed)` or `Deploy (same seed)`. Keys: I inventory panel (open/close), Escape closes the panel, Q / E previous / next operative in the panel, arrows + Enter move and choose in the panel, R interact (search / open a container), Space tactical pause, Shift queue modifier, X stop, Tab switch character, F6 regenerate the same seed, F7 new seed, F5 next fog preset, F1 developer overlay, F12 truth view. Controller: the select button (View / Create / -) toggles the panel; inside it the D-pad or left stick moves the focus, Confirm chooses, Cancel closes, LB / RB switch operative. While the panel is open every gameplay action is off (no orders, no pause key, no F-keys).

Prototype items: Service Rifle (Ranged), Marksman Rifle (Marksman), Combat Blade (Melee), Light Vest (+20 max health), Servo Boots (+0.5 m/s), Medkit (heals 40, stacks to 3). Starter: Darius and Sable carry an equipped Service Rifle and 2 Medkits, Kestrel an equipped Marksman Rifle and 2 Medkits; the stash holds a Combat Blade, a Service Rifle, a Light Vest, Servo Boots and 4 Medkits. A bag holds 8 entries. Containers are orange boxes (3 per mission when they fit); the first R is a 1.5 s search, later ones open at once.

**Hardware status.** No controller has been tested on physical hardware in this phase. The only hardware check so far is the owner's DualSense in Phase 6.5 (the layout of decision 024). The inventory panel and its pad navigation have been exercised with simulated Input System devices only, so rows 26 to 29 are all open. The console must stay clean throughout (no exceptions; the only expected warning is a loot shortfall, if a layout cannot fit every container).

## Automated results (separate from the manual checks above)

Final runs on 2026-10-10 (after the playtest follow-up wave), batch mode, Unity 6000.3.25f1, `Tools/run-tests.sh` (Unity Editor closed):

- EditMode: `result="Passed" total="1159" passed="1159" failed="0" skipped="0"`, EXIT=0 (Phase 11.5 baseline 1052 + 107 new).
- PlayMode: `result="Passed" total="1206" passed="1206" failed="0" skipped="0"`, EXIT=0 (Phase 11.5 baseline 1050 + 156 new).

Automated coverage includes (beyond the Phase 12 list below): the close-deploys rule, equip from the stash, mouse drag and drop (rules and events), the timed gear swap (time, cancel, pause, death, steering, queueing, outcome messages, the working-state-only rule), crate placement against walls with a clear lane, the Bag chip, and walks to crates and terminals on generated missions. The Phase 12 list: item data and validation, transfers that never duplicate or destroy, loadout and stash edits with the in-mission lock, session and working state settlement (success once, failure, abort, failed generation, same seed twice), equipment-driven configuration and the no-weapon refusal, spawned units' weapon visuals (including hidden hostiles), item use and collect orders (pause, stop, replace, death, two collectors, full bag), deterministic loot placement and container fog rules, the input gate and the release gate, the inventory panel (buttons, tabs, cancel, deploy, mission end), the scene wiring, and the HUD fog sweep with an unsearched and a searched container under the Blind preset.

Not covered by any automated test: anything on physical controllers, focus movement with a live EventSystem, how the panel and the weapons look on screen, and builds (no player build was made). The seeded HUD and fog scene tests (the Phase 11 / 11.5 sweeps over generated missions) run without a loot table, so containers are not part of those seeded sweeps; only the dedicated Blind-preset container sweep covers them.
