# Phase 13 Stage 3: accounts and development authentication, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

Date: 2026-10-14. Status: **revision 2, approved for implementation by the owner on 2026-10-14** (Q1–Q3 answered as recommended; the account id changed to a sequential `BIGINT` shown as Base58, see "Revision 2" below, which **supersedes every conflicting line of this plan**). **Every test count below is a prediction, not a measurement.**

**Goal:** accounts with permanent PostgreSQL-generated `BIGINT` ids, shown outside the database as canonical Base58 strings, development keys issued once by an operator, opaque revocable access tokens, `GET /v1/me`, and an operator credential lifecycle (rotate, revoke, revoke sessions, suspend, reactivate). It is secure by default (dev login and admin routes off unless configured) and proven against a real PostgreSQL 17.

**Architecture:**
- **Domain.** `Accounts.Domain` gains pure secret and handle rules (256-bit opaque secrets, only their SHA-256 stored) and the Base58 account-id codec with its JSON converter, the only place an account id changes form.
- **Persistence.** `Accounts.Persistence` gains two Dapper stores, one per aggregate: `AccountAdminStore` (operator lifecycle, audited in `operator_actions`) and `SessionStore` (login, authenticate, logout). Every check uses the database clock.
- **API.** `Accounts.Api` gains a custom bearer authentication handler (ASP.NET Core's in-box authentication, no JWT library), the login, logout and `me` endpoints, ASP.NET Core's in-box rate limiter, a gated admin route, and an `admin` CLI command.
- **Migration.** `0001_accounts_and_auth` creates the tables and carries the Stage 1 follow-up: the global revoke of `PUBLIC` `EXECUTE` on the migrator's future functions.

**Tech stack:** .NET 10, ASP.NET Core minimal APIs (in-box authentication, authorization and rate limiting), Npgsql 10.0.3, Dapper 2.1.89, xUnit 2.9.3, PostgreSQL 17 (test cluster `blackglass-test` on `127.0.0.1:55432` through the SSH tunnel). No new package.

## Global Constraints

- **Scope.** Accounts, development authentication, the operator credential lifecycle and their tests. **No** operatives, inventory, energy, insurance, attempts, the mission host, the Unity client, or any production authentication provider (CLAUDE.md). No live accounts-stack deployment; VM evidence uses the throwaway Compose projects only.
- **Secrets.**
  - Account keys and access tokens are 256-bit (`RandomNumberGenerator`), shown exactly once.
  - Only `SHA-256` of the 32 raw bytes is stored. "High-entropy random keys need no slow hash" (§4.2).
  - No secret appears in Git, logs, responses (other than the one-time issue), receipts or error bodies.
  - Logs show at most an 8-hex prefix of a hash (§4.4).
- **Identity.**
  - `account_id` is `bigint generated always as identity` (decision 048 amendment, spec §4.1 revision 2.2): generated by PostgreSQL only, positive, permanent, never reused. C# code uses `long`. Outside the database it is the canonical Base58 string (JSON string, never a number), converted only by `AccountId` and `AccountIdJsonConverter`. No Base58 string is stored.
  - Credential and session ids stay UUIDv7 (`Guid.CreateVersion7()`); tokens and keys stay opaque.
  - "Every client endpoint takes the account from the token, never from the body" (§4.2).
- **Default off.** "The dev provider and the `/dev/v1/*` admin routes are disabled unless configured on, need a separate admin key, and are reachable on loopback only" (§4.2).
  - Disabled means the route is not mapped (404).
  - Any setting value other than the documented ones refuses to start (fail closed).
- **Database clock.** Expiry and revocation are decided by PostgreSQL `now()`, never the API clock. Tests backdate rows; they never mock the clock or sleep (§18.1 layer 3).
- **SQL.** Parameterized only; "a source audit bans string-built SQL" (Stage 3, §13.2). The app role stays DML-only; `operator_actions` is append-only for it.
- **Exposure unchanged.** The API stays on `127.0.0.1:5080` only and PostgreSQL has no ports. No UFW, SSH, Docker daemon or firewall change.
- **Migrations.** `0000` is never edited. `0001` is forward-only, checksummed and contiguous. Every next-version test file name is derived from `MigrationCatalog.Embedded.LatestVersion + 1`, never hard-coded.
- **Builds.** Use `bash ../.claude/scratchpad/phase13/tools/dt.sh test …` from `Backend/` (the CET wrapper). `UNIT` = `--filter "Requires!=Postgres"`; database tests carry `[Trait("Requires", "Postgres")]`.
- **Commits.** On branch `phase13-stage3` (from `main` `b6f7e1d`), logically separated, with trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No merge or push without the owner. The owner's two Unity settings files and `.claude/` stay untouched.

## Review Focus

Each item below is pinned by a test in the named task.

1. **Revoke during use.** A token revoked by logout, rotation, credential revocation or suspension must fail on the very next request, with no cache or grace period. Task 7: `A_revoked_token_fails_on_the_next_request`, one case per revocation path.
2. **Reactivation must not resurrect sessions.** A suspended account that is reactivated must not find its old tokens working again. Task 5: `Reactivation_does_not_restore_revoked_sessions`.
3. **Malformed bearer values.** Wrong prefix, extra whitespace, a lower-case `bearer` scheme, two `Authorization` headers, a 1 MB header, or non-canonical base64url must all give a uniform 401 with no 500 (as built: a 1 MB header is refused by Kestrel with 431 before the app sees it). Task 7: `Malformed_authorization_values_are_the_uniform_401`, `Two_separate_authorization_fields_are_401_even_when_both_are_valid` (raw TCP: HttpClient folds repeated headers into one line) and `Two_authorization_headers_or_a_huge_one_are_refused_not_500`.
4. **A database outage during authentication.** It must give 503, not a 401 that tells the client its token is bad, and log no secret. Task 7: `Authentication_during_a_database_outage_is_503_never_401` (login too).
5. **Two operators race on one account.** For example, rotation against suspension, or two rotations at once. The result must leave exactly one consistent state, never two live credentials or a live session on a suspended account. Task 4: `Concurrent_rotations_leave_exactly_one_live_credential` and `Rotation_racing_suspension_leaves_no_live_session`. The `0001_revocations_cascade` invariant checks this after every database test class.
6. **Login racing a revocation.** A login that overlaps a rotation, a credential revocation or a suspension must never leave a live session on a revoked credential or a suspended account once the revocation has committed. Task 5: `Login_waits_for_an_in_flight_revocation_and_then_fails` (deterministic: the test holds the account lock) and the repeated race tests.
7. **Guessable ids grant nothing.** Account ids are sequential. Account A, knowing or guessing B's Base58 id, must get nothing of B's from any route, header or body. Task 10: `AuthorizationTests`.
8. **The public id form.** Every account id leaving the API is a canonical Base58 JSON string; no response type serializes a `long` account id as a number. Task 2 (codec, known-answer vectors) and Task 10 (`DtoAuditTests`).

## Revision 2 (owner, 2026-10-14): account ids and the Stage 3 rulings

The owner approved Stage 3 with Q1–Q3 answered as recommended, and changed the account id architecture (decision 048 amendment; spec revision 2.2, §0.2, §4.1, §4.7, §15.1, §16). **Where a task's text or code listing below conflicts with this section, this section wins.** The listings that still show `Guid` account ids are the revision-1 draft; the implementation follows the deltas here, and Task 12 records the as-built result.

**General rules (all tasks):**
- **Account ids.** `long` in C#, `bigint` in SQL, minted only by `accounts.account_id bigint generated always as identity`. Every account column and foreign key is `bigint`. Credential and session ids stay `Guid.CreateVersion7()`.
- **One conversion boundary.** `Blackglass.Accounts.Domain.Accounts.AccountId` (`Format(long)`, `TryParse(string?, out long)`) and `AccountIdJsonConverter : JsonConverter<long>`. Response properties that carry an account id use `[property: JsonConverter(typeof(AccountIdJsonConverter))]`. Stores, claims and rules never see Base58. The admin CLI's `--account` takes and prints Base58. Account-lookup log lines use `AccountId.Format`.
- **No account in a client request.** Unchanged (§4.2), and now with IDOR tests that use guessed sequential ids (Task 10).
- **Not a secret.** No route, error or log distinguishes "no such account" from "not yours" for a client.

**Per-task deltas:**

- **Task 1.** Unchanged.
- **Task 2: adds the account-id codec and display names.** Files: `Backend/src/Accounts.Domain/Accounts/{AccountId,AccountIdJsonConverter}.cs`, `Backend/src/Accounts.Domain/Auth/DisplayName.cs`, and tests `Backend/tests/Accounts.Domain.Tests/Accounts/{AccountIdTests,AccountIdJsonConverterTests}.cs` and `Auth/DisplayNameTests.cs`.
  - `AccountId`: `const string Alphabet = "123456789ABCDEFGHJKLMNPQRSTUVWXYZabcdefghijkmnopqrstuvwxyz"`, `const int MaxLength = 11`, `static string Format(long id)` (throws `ArgumentOutOfRangeException` for `id <= 0`), and `static bool TryParse(string? text, out long id)`. Parsing is strict: 1–11 characters, alphabet only (ordinal, so case-sensitive, and no whitespace, sign or non-ASCII digit), no leading `1`, at most `long.MaxValue`.
  - **Known-answer vectors**, not produced by the encoder under test:
    - published: draft-msporny-base58 test vector `0x0000287fb4cd` → `11233QC4`, whose numeric part `0x287fb4cd` = 679457997 → `233QC4`;
    - the owner's example 123456789 → `BukQL`;
    - boundaries computed independently (Python big integers): 1 → `2`, 57 → `z`, 58 → `21`, 3363 → `zz`, 3364 → `211`, 2147483647 → `4GmR58`, 4294967296 → `7YXq9H`, 2^53 → `2DLNrMSKuh`, 2^53+1 → `2DLNrMSKui`, 58^10−1 → `zzzzzzzzzz`, 58^10 → `21111111111`, `long.MaxValue` → `NQm6nKp8qFC`.
  - **Rejections:** null; empty; `1`, `11` and `12` (leading zero digit); `0`, `O`, `I`, `l`; leading, trailing or inner whitespace; `+2` and `-2`; a full-width digit; `NQm6nKp8qFD` (`long.MaxValue + 1`); `zzzzzzzzzzz`; any 12-character string. `BUKQL` parses to a different number than `BukQL` (case matters).
  - **Round trip:** 10 000 random positive `long`s round-trip, and `Format` never pads.
  - **Converter:** it writes a JSON string. It reads only a canonical string; a JSON number, `null`, or a malformed or non-canonical string throws `JsonException`.
  - `DisplayName.IsValid`: 1–64 characters, no control character, no leading or trailing whitespace.
- **Task 3: the `bigint` schema** (it replaces the listing's SQL; the spec's §15.1 `0001` block is the same):
  - `accounts.account_id bigint generated always as identity primary key check (account_id > 0)`; `display_name` optional (the `DisplayName` rule as a check).
  - `account_identities` (provider `dev`, the handle as subject) is **optional**: at most one per account (`unique (provider, account_id)`), created only when the operator gives a handle (owner: "an optional development handle or display name"). The `0001_accounts_have_one_dev_identity` invariant is dropped.
  - `dev_credentials`: `account_id bigint`. A partial unique index, `dev_credentials_one_live`, allows at most one live credential per account.
  - `auth_sessions`: `account_id bigint`, with the composite FK to `(credential_id, account_id)`.
  - `operator_actions` adds `correlation_id uuid not null` and `credential_id uuid references dev_credentials`; its `account_id bigint references accounts`.
  - **Privileges.** `accounts_app` gets column-level `INSERT (status, display_name)` and `UPDATE (status, display_name)` on `accounts`; `UPDATE (revoked_at)` on `dev_credentials` and `auth_sessions`; no `UPDATE` on `account_identities`; no `DELETE` anywhere in `0001`; `operator_actions` append-only. So the app can never choose an account id (not even with `OVERRIDING SYSTEM VALUE`), change a primary key, or re-point a key.
  - **New schema tests:**
    - ids are generated 1, 2, 3 in a fresh database;
    - a rolled-back insert leaves a gap and the id is never reused;
    - the app can't insert an `account_id` (42501), even with `OVERRIDING SYSTEM VALUE`, and can't update or delete one;
    - every `account_id` column in the schema is `bigint`;
    - FKs refuse an unknown account (23503);
    - two live credentials for one account are refused (23505);
    - the function `EXECUTE` revoke, tested with a function the migrator creates after `0001`.
- **Task 4: `long` ids, optional handle and display name, correlation ids.**
  - `OperatorContext(string Operator, string Reason, Guid CorrelationId)`, where `Create` mints `Guid.CreateVersion7()`.
  - `IssuedCredential(long AccountId, Guid CredentialId, OpaqueSecret AccountKey)`.
  - `CreateAccountAsync(string? handle, string? displayName, OperatorContext op, …)`.
  - The lifecycle methods take `long accountId`. `AccountAdminError` gains `InvalidDisplayName`.
  - The audit row carries `correlation_id`, `account_id` and `credential_id`.
  - Lock order everywhere: the account row (`FOR UPDATE`) first, then credentials, then sessions.
  - **New tests:** `An_audit_failure_rolls_back_the_change` (an over-long reason that bypasses `OperatorContext.Create` fails the audit insert after the state change; nothing persists); `Created_accounts_get_sequential_ids`; and audit rows never hold the key or its hash.
- **Task 5: login takes locks.** `LoginAsync` is one transaction:
  1. find the credential's account by key hash;
  2. lock the account `FOR SHARE` and require `active`;
  3. lock the credential `FOR SHARE` and require it live and the account's;
  4. insert the session.

  Every admin mutation locks the account `FOR UPDATE` first, so a login and a revocation serialize. A login that waited sees the committed revocation and fails; a session committed before the revocation is revoked by it. `AuthenticateAsync` still checks the credential and the account on every request. `RevokeAsync(Guid sessionId, long accountId)` names both.
  - **New tests:**
    - `Login_waits_for_an_in_flight_revocation_and_then_fails`, for rotation, credential revocation and suspension (the test holds the account row `FOR UPDATE` in its own transaction, asserts the login is still pending, revokes and commits, then expects null);
    - `Concurrent_logins_and_rotations_leave_no_live_session_on_a_revoked_credential` (repeated races, then the invariant);
    - a login racing a suspension;
    - multiple sessions per credential.
- **Task 6: two more limits.** `BLACKGLASS_RATE_LOGIN_GLOBAL_PER_MINUTE` (1–100000, default 60; the revision-1 draft hard-coded 6× the per-key limit) and `BLACKGLASS_RATE_ADMIN_PER_MINUTE` (1–1000, default 10).
- **Task 7: Base58 in responses; logout repeat behaviour.**
  - `LoginResponse.AccountId` and `MeResponse.AccountId` are `long` with the converter; `/v1/me` is exactly `{"accountId":"<Base58>"}`.
  - Claims hold the decimal id internally; `AccountClaims.AccountOf` returns `long`.
  - A database outage during **login** is also 503.
  - **Repeated logout:** logout needs a valid session, so a second logout with the same token is the uniform 401 that any unknown, expired or revoked token gets. It is harmless (nothing changes) and reveals nothing (an arbitrary token gets the same 401). Other sessions of the same account and credential stay valid. Tests: `Repeated_logout_is_the_uniform_401_and_changes_nothing` and `Logout_revokes_only_the_current_session`.
- **Task 8: the global login limit test.** `Fabricated_keys_cannot_bypass_the_global_login_limit`: distinct well-formed keys exhaust the global window, then a valid key also gets 429.
- **Task 9: Base58 at the operator surfaces.**
  - CLI: `--account <Base58>`; `account create [--handle <h>] [--display-name <name>]`. `create` and `rotate` print `accountId=<Base58>`, `credentialId=<uuid>`, `accountKey=<dk1_…>` and `correlationId=<uuid>`; the others print their summary and `correlationId`.
  - Route: `POST /dev/v1/accounts` `{handle?, displayName?, operator, reason}` → 201 `{accountId: "<Base58>", credentialId, accountKey}` with `Cache-Control: no-store` and `X-Correlation-Id`, and no `Location` (no readable account resource exists).
  - The admin group is rate-limited (policy `admin`, one global window, applied before the key check). A rejected admin request logs a sanitized warning: the reason and the correlation id, never the presented key. A player bearer token never authorizes it.
  - **New tests:** a player token, in `Authorization` or in `X-Admin-Key`, gets 401; the admin rate limit; the CLI's Base58 `--account` refuses malformed and non-canonical ids (64) and unknown ones (65).
- **Task 10: IDOR tests.** New `Backend/tests/Accounts.Integration.Tests/Database/AuthorizationTests.cs`:
  - A's token with B's Base58 id (B = A + 1, guessed) in the query, the body, an `X-Account-Id` header, or a path such as `/v1/accounts/{B}` gets only A's data, or the same 404 A's own id gets;
  - B's id as a bearer token or an admin key gets 401;
  - logout with B's id in the body revokes only A's session.

  `DtoAuditTests` also checks that every response type's `*AccountId` property is a `long` with `AccountIdJsonConverter`, and that it serializes as a string.
- **Task 11.** Adds the two new rate variables to Compose and the README.
- **Task 12.** Aligns §4.2, §16.1 and §19 with the as-built Stage 3, and updates `CLAUDE.md`.

    using System.Buffers.Text;
    using System.Security.Cryptography;

    namespace Blackglass.Accounts.Domain.Auth;

    /// <summary>
    /// A 256-bit random secret shown once: a development account key ("dk1") or an access token ("at1"). Its text form is
    /// "&lt;prefix&gt;_&lt;43 base64url characters&gt;". Only SHA-256 of the 32 raw bytes is ever stored or compared (spec §4.2:
    /// high-entropy random secrets need no slow hash). TryParse is strict: the exact prefix and exactly 32 canonically
    /// encoded bytes. ToString never reveals the secret.
    /// </summary>
    public sealed class OpaqueSecret
    {
        public const int Bytes = 32;
        public const string AccountKeyPrefix = "dk1";
        public const string AccessTokenPrefix = "at1";
        const int EncodedLength = 43;

        readonly byte[] raw;

        OpaqueSecret(string prefix, byte[] raw) => (Prefix, this.raw) = (prefix, raw);

        public string Prefix { get; }
        public string Text => Prefix + "_" + Base64Url.EncodeToString(raw);

        public static OpaqueSecret New(string prefix) => new(prefix, RandomNumberGenerator.GetBytes(Bytes));

        public byte[] Hash() => SHA256.HashData(raw);

        public static bool TryParse(string? text, string prefix, out OpaqueSecret? secret)
        {
            secret = null;
            if (text is null || text.Length != prefix.Length + 1 + EncodedLength || !text.StartsWith(prefix + "_", StringComparison.Ordinal))
                return false;
            var encoded = text.AsSpan(prefix.Length + 1);
            Span<byte> buffer = stackalloc byte[Bytes + 2];
            if (!Base64Url.TryDecodeFromChars(encoded, buffer, out var written) || written != Bytes)
                return false;
            var bytes = buffer[..Bytes].ToArray();
            if (!encoded.SequenceEqual(Base64Url.EncodeToString(bytes)))
                return false; // non-canonical trailing bits
            secret = new OpaqueSecret(prefix, bytes);
            return true;
        }

        /// <summary>The 8-hex prefix of a hash: the most of a secret's hash any log may show (spec §4.4).</summary>
        public static string HashPrefix(ReadOnlySpan<byte> hash) => Convert.ToHexStringLower(hash[..4]);

        public override string ToString() => Prefix + "_<redacted>";
    }

    /// <summary>
    /// The operator credential lifecycle (spec §4.2): create an account with its dev identity and first key, rotate, revoke a
    /// credential, revoke sessions, suspend and reactivate. Each call is one transaction that locks the account row first
    /// (so two operators on one account serialize) and appends one operator_actions row. Keys are returned once and never
    /// stored or recorded in plain form.
    /// </summary>

        public async Task<IssuedCredential> CreateAccountAsync(string handle, OperatorContext op, CancellationToken ct = default)
        {

                throw new AccountAdminException(AccountAdminError.InvalidHandle, "The handle must be lowercase letters and digits separated by single '.' or '-', at most 64 characters.");
            var accountId = Guid.CreateVersion7();
            var credentialId = Guid.CreateVersion7();

            await using var conn = await db.OpenConnectionAsync(ct);

            }
            await InsertCredentialAsync(conn, tx, accountId, credentialId, key, ct);
            await AuditAsync(conn, tx, op, "account_create", accountId, new { credentialId, handle }, ct);
            await tx.CommitAsync(ct);
            return new IssuedCredential(accountId, credentialId, key);
        }

        {
            var credentialId = Guid.CreateVersion7();
            var key = OpaqueSecret.New(OpaqueSecret.AccountKeyPrefix);
            await using var conn = await db.OpenConnectionAsync(ct);
            await using var tx = await conn.BeginTransactionAsync(ct);
            await LockAccountAsync(conn, tx, accountId, ct);

                new { accountId }, tx, cancellationToken: ct))).ToArray();

            await InsertCredentialAsync(conn, tx, accountId, credentialId, key, ct);
            await AuditAsync(conn, tx, op, "credential_rotate", accountId, new { credentialId, revokedCredentials = old, revokedSessions = sessions }, ct);
            await tx.CommitAsync(ct);
            return new IssuedCredential(accountId, credentialId, key);
        }

        public async Task<int> RevokeCredentialAsync(Guid credentialId, OperatorContext op, CancellationToken ct = default)
        {
            await using var conn = await db.OpenConnectionAsync(ct);
            await using var tx = await conn.BeginTransactionAsync(ct);
            var accountId = await conn.ExecuteScalarAsync<Guid?>(new CommandDefinition(
                "select account_id from dev_credentials where credential_id = @credentialId", new { credentialId }, tx, cancellationToken: ct))
                ?? throw new AccountAdminException(AccountAdminError.NotFound, "No such credential.");
            await LockAccountAsync(conn, tx, accountId, ct);
            await conn.ExecuteAsync(new CommandDefinition(
                "update dev_credentials set revoked_at = now() where credential_id = @credentialId and revoked_at is null", new { credentialId }, tx, cancellationToken: ct));
            var sessions = await conn.ExecuteAsync(new CommandDefinition(RevokeSessionsOfCredentials, new { credentials = new[] { credentialId } }, tx, cancellationToken: ct));
            await AuditAsync(conn, tx, op, "credential_revoke", accountId, new { credentialId, revokedSessions = sessions }, ct);
            await tx.CommitAsync(ct);
            return sessions;
        }

        public async Task<int> RevokeSessionsAsync(Guid accountId, OperatorContext op, CancellationToken ct = default)
        {
            await using var conn = await db.OpenConnectionAsync(ct);
            await using var tx = await conn.BeginTransactionAsync(ct);
            await LockAccountAsync(conn, tx, accountId, ct);
            var sessions = await RevokeAllSessionsAsync(conn, tx, accountId, ct);
            await AuditAsync(conn, tx, op, "sessions_revoke", accountId, new { revokedSessions = sessions }, ct);
            await tx.CommitAsync(ct);
            return sessions;
        }

        public async Task<int> SuspendAsync(Guid accountId, OperatorContext op, CancellationToken ct = default)
        {
            await using var conn = await db.OpenConnectionAsync(ct);
            await using var tx = await conn.BeginTransactionAsync(ct);
            await LockAccountAsync(conn, tx, accountId, ct);
            await conn.ExecuteAsync(new CommandDefinition("update accounts set status = 'suspended' where account_id = @accountId", new { accountId }, tx, cancellationToken: ct));
            var sessions = await RevokeAllSessionsAsync(conn, tx, accountId, ct);
            await AuditAsync(conn, tx, op, "account_suspend", accountId, new { revokedSessions = sessions }, ct);
            await tx.CommitAsync(ct);
            return sessions;
        }

        public async Task ReactivateAsync(Guid accountId, OperatorContext op, CancellationToken ct = default)
        {
            await using var conn = await db.OpenConnectionAsync(ct);
            await using var tx = await conn.BeginTransactionAsync(ct);
            await LockAccountAsync(conn, tx, accountId, ct);
            await conn.ExecuteAsync(new CommandDefinition("update accounts set status = 'active' where account_id = @accountId", new { accountId }, tx, cancellationToken: ct));
            await AuditAsync(conn, tx, op, "account_reactivate", accountId, new { }, ct);
            await tx.CommitAsync(ct);
        }

        static async Task LockAccountAsync(NpgsqlConnection conn, NpgsqlTransaction tx, Guid accountId, CancellationToken ct)
        {
            var found = await conn.ExecuteScalarAsync<Guid?>(new CommandDefinition(
                "select account_id from accounts where account_id = @accountId for update", new { accountId }, tx, cancellationToken: ct));
            if (found is null) throw new AccountAdminException(AccountAdminError.NotFound, "No such account.");
        }

        static Task<int> RevokeAllSessionsAsync(NpgsqlConnection conn, NpgsqlTransaction tx, Guid accountId, CancellationToken ct) =>
            conn.ExecuteAsync(new CommandDefinition(
                "update auth_sessions set revoked_at = now() where account_id = @accountId and revoked_at is null", new { accountId }, tx, cancellationToken: ct));

        static Task InsertCredentialAsync(NpgsqlConnection conn, NpgsqlTransaction tx, Guid accountId, Guid credentialId, OpaqueSecret key, CancellationToken ct) =>
            conn.ExecuteAsync(new CommandDefinition(
                "insert into dev_credentials (credential_id, account_id, secret_hash) values (@credentialId, @accountId, @hash)",
                new { credentialId, accountId, hash = key.Hash() }, tx, cancellationToken: ct));

        static Task AuditAsync(NpgsqlConnection conn, NpgsqlTransaction tx, OperatorContext op, string action, Guid accountId, object result, CancellationToken ct) =>
            conn.ExecuteAsync(new CommandDefinition(
                "insert into operator_actions (operator, action, account_id, reason, checks, result) values (@operator, @action, @accountId, @reason, '{}'::jsonb, @result::jsonb)",
                new { @operator = op.Operator, action, accountId, reason = op.Reason, result = JsonSerializer.Serialize(result) }, tx, cancellationToken: ct));

  using Dapper;
  using Npgsql;
  using Blackglass.Accounts.Domain.Auth;

  namespace Blackglass.Accounts.Persistence.Accounts;

  public sealed record IssuedSession(Guid SessionId, Guid AccountId, DateTimeOffset ExpiresAt, OpaqueSecret AccessToken);

  public sealed record AuthenticatedSession(Guid SessionId, Guid AccountId);

  /// <summary>
  /// Development login and token authentication (spec §4.2). Every check runs in PostgreSQL against now(): an expired,
  /// revoked, or suspended-account session is refused by the same query on every request, with no cache, so revocation is
  /// immediate. Only SHA-256 hashes cross this boundary inward.
  /// </summary>
  public sealed class SessionStore(NpgsqlDataSource db)
  {
      const string LoginSql = """
          insert into auth_sessions (session_id, account_id, credential_id, token_hash, expires_at)
          select @sessionId, c.account_id, c.credential_id, @tokenHash, now() + make_interval(mins => @minutes)
          from dev_credentials c
          join accounts a on a.account_id = c.account_id
          where c.secret_hash = @keyHash and c.revoked_at is null and a.status = 'active'
          returning account_id as AccountId, expires_at as ExpiresAt
          """;

      const string AuthenticateSql = """
          select s.session_id as SessionId, s.account_id as AccountId
          from auth_sessions s
          join dev_credentials c on c.credential_id = s.credential_id
          join accounts a on a.account_id = s.account_id
          where s.token_hash = @tokenHash and s.revoked_at is null and s.expires_at > now()
            and c.revoked_at is null and a.status = 'active'
          """;

      sealed record LoginRow(Guid AccountId, DateTimeOffset ExpiresAt);

      public async Task<IssuedSession?> LoginAsync(byte[] accountKeyHash, int lifetimeMinutes, CancellationToken ct = default)
      {
          var sessionId = Guid.CreateVersion7();
          var token = OpaqueSecret.New(OpaqueSecret.AccessTokenPrefix);
          await using var conn = await db.OpenConnectionAsync(ct);
          var row = await conn.QuerySingleOrDefaultAsync<LoginRow>(new CommandDefinition(LoginSql,
              new { sessionId, tokenHash = token.Hash(), minutes = lifetimeMinutes, keyHash = accountKeyHash }, cancellationToken: ct));
          return row is null ? null : new IssuedSession(sessionId, row.AccountId, row.ExpiresAt, token);
      }

      public async Task<AuthenticatedSession?> AuthenticateAsync(byte[] tokenHash, CancellationToken ct = default)
      {
          await using var conn = await db.OpenConnectionAsync(ct);
          return await conn.QuerySingleOrDefaultAsync<AuthenticatedSession>(new CommandDefinition(AuthenticateSql, new { tokenHash }, cancellationToken: ct));
      }

      public async Task<bool> RevokeAsync(Guid sessionId, CancellationToken ct = default)
      {
          await using var conn = await db.OpenConnectionAsync(ct);
          return await conn.ExecuteAsync(new CommandDefinition(
              "update auth_sessions set revoked_at = now() where session_id = @sessionId and revoked_at is null", new { sessionId }, cancellationToken: ct)) == 1;
      }
  }

  public sealed class AuthSettingsException(string message) : Exception(message);

  /// <summary>
  /// Authentication settings from the environment (spec §4.2, §19). The dev provider and the admin routes are off unless set
  /// to exactly "enabled"; any unknown value refuses to start. The admin key is read from a file and kept only as SHA-256.
  /// </summary>
  public sealed class AuthSettings
  {
      public const string DevAuthVar = "BLACKGLASS_DEV_AUTH";
      public const string AdminRoutesVar = "BLACKGLASS_ADMIN_ROUTES";
      public const string AdminKeyFileVar = "BLACKGLASS_ADMIN_KEY_FILE";
      public const string TokenLifetimeVar = "BLACKGLASS_TOKEN_LIFETIME_MINUTES";
      public const string LoginRateVar = "BLACKGLASS_RATE_LOGIN_PER_MINUTE";
      public const string RequestRateVar = "BLACKGLASS_RATE_REQUESTS_PER_MINUTE";
      public const int MinAdminKeyLength = 32;

      public bool DevAuthEnabled { get; private init; }
      public bool AdminRoutesEnabled { get; private init; }
      public byte[]? AdminKeyHash { get; private init; }
      public int TokenLifetimeMinutes { get; private init; }
      public int LoginPerMinute { get; private init; }
      public int RequestsPerMinute { get; private init; }

      public static AuthSettings FromEnvironment(IReadOnlyDictionary<string, string?> env)
      {
          var admin = Switch(env, AdminRoutesVar);
          return new AuthSettings
          {
              DevAuthEnabled = Switch(env, DevAuthVar),
              AdminRoutesEnabled = admin,
              AdminKeyHash = admin ? ReadAdminKeyHash(env) : null,
              TokenLifetimeMinutes = Number(env, TokenLifetimeVar, 60, 1, 1440),
              LoginPerMinute = Number(env, LoginRateVar, 10, 1, 1000),
              RequestsPerMinute = Number(env, RequestRateVar, 120, 1, 100_000),
          };
      }

      static bool Switch(IReadOnlyDictionary<string, string?> env, string name) =>
          !env.TryGetValue(name, out var v) || string.IsNullOrEmpty(v) ? false
          : v == "enabled" ? true
          : v == "disabled" ? false
          : throw new AuthSettingsException($"{name} must be 'enabled' or 'disabled'.");

      static int Number(IReadOnlyDictionary<string, string?> env, string name, int fallback, int min, int max)
      {
          if (!env.TryGetValue(name, out var v) || string.IsNullOrEmpty(v)) return fallback;
          if (int.TryParse(v, NumberStyles.None, CultureInfo.InvariantCulture, out var n) && n >= min && n <= max) return n;
          throw new AuthSettingsException($"{name} must be a whole number from {min} to {max}.");
      }

      static byte[] ReadAdminKeyHash(IReadOnlyDictionary<string, string?> env)
      {

              throw new AuthSettingsException($"{AdminRoutesVar}=enabled needs {AdminKeyFileVar}.");

          catch (Exception e) when (e is IOException or UnauthorizedAccessException) { throw new AuthSettingsException($"{AdminKeyFileVar} can't be read ({e.GetType().Name})."); }

    using System.Security.Claims;
    using System.Text.Encodings.Web;
    using Microsoft.AspNetCore.Authentication;
    using Microsoft.Extensions.Options;
    using Npgsql;
    using Blackglass.Accounts.Domain.Auth;
    using Blackglass.Accounts.Persistence.Accounts;

    namespace Blackglass.Accounts.Api.Auth;

    /// <summary>
    /// "Authorization: Bearer at1_…" → the session's account (spec §4.2). Exactly one header, the exact scheme and one space,
    /// a strictly parsed token, then one database check per request (no cache, so revocation is immediate). Failures are a
    /// uniform 401; the log names the reason and at most an 8-hex hash prefix. A database outage is not a bad token: it
    /// surfaces as 503 (see AuthEndpoints' outage filter), never 401.
    /// </summary>
    public sealed class BearerAuthenticationHandler(IOptionsMonitor<AuthenticationSchemeOptions> options, ILoggerFactory logger, UrlEncoder encoder, SessionStore sessions)
        : AuthenticationHandler<AuthenticationSchemeOptions>(options, logger, encoder)
    {
        const string Prefix = "Bearer ";

        protected override async Task<AuthenticateResult> HandleAuthenticateAsync()
        {
            var values = Request.Headers.Authorization;
            if (values.Count == 0) return AuthenticateResult.NoResult();
            if (values.Count != 1 || values[0] is not { } header || !header.StartsWith(Prefix, StringComparison.Ordinal))
                return Fail("malformed authorization header");
            if (!OpaqueSecret.TryParse(header[Prefix.Length..], OpaqueSecret.AccessTokenPrefix, out var token))
                return Fail("malformed token");
            var hash = token!.Hash();
            var session = await sessions.AuthenticateAsync(hash, Context.RequestAborted); // NpgsqlException propagates → 503
            if (session is null) return Fail($"unknown, expired or revoked token {OpaqueSecret.HashPrefix(hash)}");
            var identity = new ClaimsIdentity(
                [new Claim(AccountClaims.AccountId, session.AccountId.ToString()), new Claim(AccountClaims.SessionId, session.SessionId.ToString())],
                AccountClaims.Scheme);
            return AuthenticateResult.Success(new AuthenticationTicket(new ClaimsPrincipal(identity), AccountClaims.Scheme));
        }

        AuthenticateResult Fail(string reason)
        {
            Logger.LogInformation("Authentication failed: {Reason}", reason);
            return AuthenticateResult.Fail(reason);
        }

        protected override Task HandleChallengeAsync(AuthenticationProperties properties)
        {
            Response.StatusCode = StatusCodes.Status401Unauthorized;
            Response.Headers.WWWAuthenticate = "Bearer";
            return Task.CompletedTask;
        }
    }

    using Blackglass.Accounts.Domain.Auth;

    namespace Blackglass.Accounts.Api.Auth;

    /// <summary>
    /// Login limits (spec §19: login 10/min). Behind the SSH tunnel and docker-proxy every request reaches the container from
    /// one bridge address, so a per-IP limit would be one global limit: the limit is per presented key (its hash prefix), plus
    /// a global cap of six times that. Per-IP limits wait for Phase 14's HAProxy (forwarded addresses).
    /// </summary>
    public sealed class LoginThrottle(AuthSettings settings) : IDisposable
    {
        readonly PartitionedRateLimiter<string> perKey = PartitionedRateLimiter.Create<string, string>(key =>
            RateLimitPartition.GetFixedWindowLimiter(key, _ => new FixedWindowRateLimiterOptions
            { PermitLimit = settings.LoginPerMinute, Window = TimeSpan.FromMinutes(1), QueueLimit = 0 }));
        readonly FixedWindowRateLimiter global = new(new FixedWindowRateLimiterOptions
        { PermitLimit = settings.LoginPerMinute * 6, Window = TimeSpan.FromMinutes(1), QueueLimit = 0 });

        public bool TryAcquire(byte[] keyHash)
        {
            using var keyLease = perKey.AttemptAcquire(OpaqueSecret.HashPrefix(keyHash));
            if (!keyLease.IsAcquired) return false;
            using var globalLease = global.AttemptAcquire();
            return globalLease.IsAcquired;
        }

        public void Dispose() { perKey.Dispose(); global.Dispose(); }
    }

    using Blackglass.Accounts.Persistence.Accounts;

    namespace Blackglass.Accounts.Api.Admin;

    public sealed class AdminUsageException(string message) : Exception(message);

    /// <summary>The admin CLI's strict grammar: "&lt;noun&gt; &lt;verb&gt;" then known flags, each once, all required ones present.</summary>
    public sealed record AdminArguments(string Verb, string? Handle, Guid? Account, Guid? Credential, OperatorContext Operator)
    {
        public const string Usage =
            "usage: Accounts.Api admin account create --handle <h> | credential rotate --account <id> | credential revoke --credential <id> | " +
            "sessions revoke --account <id> | account suspend --account <id> | account reactivate --account <id>; each with --operator <name> --reason <text>";

        static readonly Dictionary<string, string> Target = new()
        {
            ["account-create"] = "--handle", ["credential-rotate"] = "--account", ["credential-revoke"] = "--credential",
            ["sessions-revoke"] = "--account", ["account-suspend"] = "--account", ["account-reactivate"] = "--account",
        };

        public static AdminArguments Parse(IReadOnlyList<string> args)
        {
            if (args.Count < 2) throw new AdminUsageException(Usage);
            var verb = args[0] + "-" + args[1];
            if (!Target.TryGetValue(verb, out var targetFlag)) throw new AdminUsageException(Usage);
            var flags = new Dictionary<string, string>(StringComparer.Ordinal);
            for (var i = 2; i < args.Count; i += 2)
            {
                if (i + 1 >= args.Count || args[i] is not ("--handle" or "--account" or "--credential" or "--operator" or "--reason")
                    || !flags.TryAdd(args[i], args[i + 1]))
                    throw new AdminUsageException(Usage);
            }
            if (!flags.Keys.Order().SequenceEqual(new[] { targetFlag, "--operator", "--reason" }.Order())) throw new AdminUsageException(Usage);
            OperatorContext op;
            try { op = OperatorContext.Create(flags["--operator"], flags["--reason"]); }
            catch (ArgumentException e) { throw new AdminUsageException(e.Message); }
            Guid? Id(string flag) => !flags.TryGetValue(flag, out var v) ? null
                : Guid.TryParseExact(v, "D", out var g) ? g : throw new AdminUsageException($"{flag} must be a UUID.");
            return new AdminArguments(verb, flags.GetValueOrDefault("--handle"), Id("--account"), Id("--credential"), op);
        }
    }

**Decisions made in this plan (say if you want any changed):**
- **Credential-linked sessions.** `auth_sessions` gains `credential_id`, with a composite FK to the credential's account. Without it, revoking or rotating one key couldn't revoke the sessions it created. This deviates from the §15.1 draft.
- **Dev identity.** The dev identity's subject is an operator-chosen handle (lowercase id rule) with one dev identity per account. The handle is never shown to clients and never becomes the account id.
- **Uniform 401.** Bad, expired, revoked, suspended and malformed all give the same 401 with an empty body, so there's no oracle. The reason is logged with at most an 8-hex hash prefix.
- **Database outage.** A database outage during authentication is 503, never 401.
- **Lifecycle rules.**
  - Rotation revokes all previous credentials and their sessions in the same transaction.
  - Suspension revokes all sessions, and reactivation restores none.
  - Every lifecycle call locks the account row, so concurrent operators serialize.
- **Logout.** `POST /v1/auth/logout` (204) is added for client-side token revocation; it isn't in §16.1.
- **Rate limits.**
  - Login is limited per presented key (§19's 10/min), plus a global cap of 60/min.
  - Authenticated requests are limited per account (120/min).
  - A per-IP limit is meaningless behind the SSH tunnel and docker-proxy, where every request comes from one bridge address. It is deferred to Phase 14's HAProxy and documented.
- **Admin loopback.** For the admin routes, "loopback only" is enforced by the API's `127.0.0.1` publication, plus the off-by-default flag and the admin key. An in-container address check would see the bridge gateway, not loopback.
- **Formats.** Account keys are `dk1_` and tokens `at1_`, each followed by base64url of 32 random bytes. SHA-256 is taken of the raw bytes. The prefixes are versioned and name no product.
- **Token lifetime.** A fixed 60 minutes (configurable) with no refresh token: a client logs in again. Expired session rows are kept; cleanup or retention is a Phase 14 item.
- **Migrator fix.** The migrator's interpolated `set local lock_timeout` becomes a parameterized `set_config`, the source audit's one finding in existing code.
- **Version-agnostic tests.** Task 1 makes the remaining hard-coded `0001` probes version-agnostic before `0001` exists (the owner's carry-over). The drill and smoke tests derive their versions already.
- **Unity.** No Unity change in Stage 3.
